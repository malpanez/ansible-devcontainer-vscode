# v2.2.0

v2.2.0 moves the Debian images to Debian 13 and fixes what went wrong when these images were opened in VS Code, mostly on a fresh machine. The image changes reach a template when Renovate moves its pin to the v2.2.0 images, a minor update that merges on green; until then the templates keep opening the image they pin. The template changes below apply at once.

- Your git name, email and aliases reach the container. The Dev Containers extension copies your `.gitconfig` only when the container's has nothing but `[filter]` and `[safe]` sections, and the images wrote an `[init]` section to `~/.gitconfig`. `init.defaultBranch` now lives in `/etc/gitconfig`.
- Terminals open in bash on every image. The `vscode` account had `/bin/sh` as its login shell everywhere but golang.
- `ssh` is in the terraform, latex and golang images, so `git` reaches `git@` remotes and `terraform init` fetches `git::ssh://` modules. Before: `error: cannot run ssh`.
- The latex template's `postCreateCommand` no longer fails with `PermissionError` on `.lock`, and `go build` and `go get` no longer fail with permission denied in the golang template. Their named volumes were mounted on directories the images did not have, so a new volume came up owned by root.
- On a host whose uid is not 1000, the terraform template's plugin cache is writable. The extension gives `vscode` your uid and changes the owner only of its home, and the cache is outside it.
- `LANG` is `C.UTF-8` on every image, set by its own Dockerfile. terraform, latex and golang had none, so `locale charmap` printed `ANSI_X3.4-1968`; the Python-based images had it only because the python base happens to set it on some digests.
- golang carries `libstdc++`, one of VS Code's prerequisites for Alpine, so the extension no longer tries to install it when it starts.
- `podman run` works in ansible-podman with its default network. The image had `slirp4netns` but not `passt`, so it stopped at `could not find pasta`.
- `gh` in ansible-podman moves from Debian's 2.46.0 to the package from cli.github.com, as in the other images. [GitHub says](https://github.com/cli/cli/blob/trunk/docs/install_linux.md#debian-community) the 2.45 and 2.46 that distributions carry are broken by deprecated GitHub APIs.
- Building an image checks the keyring of `gh`'s package repository against the SHA256 [GitHub publishes](https://github.com/cli/cli/blob/trunk/docs/install_linux.md).
- `newuidmap` and `newgidmap` in ansible-podman have file capabilities instead of being setuid root, as in upstream's podman image. Rootless podman under Docker failed without `CAP_SYS_ADMIN` when they were setuid, with `newuidmap: write to uid_map failed: Operation not permitted`.
- base, ansible and ansible-aws no longer carry a world-writable `/tmp/uv-*.lock`.
- v2.1.0's base, terraform, terraform-aws and latex carried CVE-2026-107161 (high) in `libsasl2` with a Debian fix available, from a replayed cached `apt` layer. No image has a fixable critical or high now.
- No image installs `sudo` any more. It had no rules since July 2026 (1a62ea6), so it was a setuid root binary that only answered `sudo: a password is required`. It is gone from base, ansible, ansible-aws, ansible-podman, terraform, terraform-aws, latex and golang, about 2 MiB each, and `sudo` now fails with `command not found`. A root shell is `docker exec -u 0` from the host. `examples/*/.devcontainer/devcontainer-fast.json` ran `sudo mkdir` in `postCreateCommand` and failed with it; they no longer do.

## Templates

- The latex template no longer has the docker-in-docker feature. Nothing in it used Docker, the feature forced a privileged container, and dockerd never started anyway: its entrypoint runs `sudo`, which had no rules in these images since July 2026 and is now gone from them, so the logs showed `sudo: a password is required`. If you want Docker there, copy `features` and `containerUser` from `devcontainers/ansible/devcontainer.dind.json`.
- `devcontainers/ansible/devcontainer.dind.json` now starts dockerd, because it sets `"containerUser": "root"`. Terminals, tasks and lifecycle commands still run as `vscode`, which can reach the daemon through the `docker` group.
- `devcontainer.docker-socket.json`, in ansible and terraform, now gives you a working `docker`. It mounted the host's socket and stopped there: the images have no `docker` CLI, `vscode` was not in the socket's group, and `devcontainer up` reported success anyway. It now uses the `docker-outside-of-docker` feature with `"containerUser": "root"`, so `docker` reaches the host's daemon as `vscode`. Anything running in the container can now take over the host, so keep this profile to code you trust. The first open builds the feature on top of the image and needs `download.docker.com` and `github.com`.
- `docker run -v` in that profile takes paths on the host, not in the container. `devcontainers/ansible/README.md` shows how to mount the workspace.
- `devcontainers/ansible/devcontainer.dind.json` sets `"moby": false`, which Debian 13 requires. It also works on the older image it pins today.
- A failed `ansible-galaxy collection install` now fails `postCreateCommand` in the ansible templates. It used to print `No requirements.yml found` and succeed.
- `devcontainers/ansible/devcontainer.podman.json` now works on Docker. It could not start there, with `docker: --userns: invalid USER mode`, because `--userns=keep-id` is a Podman option. It now passes `podman-smoke-test`, runs a playbook in the Execution Environment, at host uid 1000 and 1001, and CI tests it. It does not use `--privileged`: its `runArgs` turn off seccomp, AppArmor and SELinux for the container and unmask `/proc` and `/sys`. `devcontainers/ansible/README.md` says what each one is for. It needs the v2.2.0 image, so it starts to pass when Renovate moves its pin.
- `devcontainer.podman.json` is plain JSON now, without comments, because the CI script reads it with `jq`.
- `devcontainers/ansible/devcontainer.podman-host.json` is new, for Podman as the host runtime, where `devcontainer.podman.json` fails with `newuidmap: write to uid_map failed: Operation not permitted`. It runs as `root` in the container, which rootless Podman maps to your user. Docker refuses to start it, because there that `root` would be the host's. CI does not test it.
- The Execution Environment is now `ghcr.io/ansible/community-ansible-dev-tools:v26.10.1`, in `devcontainer.podman.json`, `podman-smoke-test`, the README and the `execution-environment.yml` template. `quay.io/ansible/creator-ee` has been [archived](https://github.com/ansible/creator-ee) since August 2024. It is 1.41 GB, where `creator-ee:v0.18.0` was 747 MB. `ansible-navigator` used `:latest` of this image unless told otherwise, and pulled it on every run, so the profile now sets `ANSIBLE_NAVIGATOR_EXECUTION_ENVIRONMENT_IMAGE`. If you copied the template, its `package_manager_path` is now `/usr/bin/dnf5`, as that image's documentation says, and it no longer installs `python312` next to the image's own Python.
- The features in `devcontainer.dind.json` and `devcontainer.docker-socket.json` are pinned to exact versions, `docker-in-docker:4.1.3` and `docker-outside-of-docker:1.10.1`. `docker-in-docker` moves up from major 2 to the major its [documentation](https://github.com/devcontainers/features/tree/main/src/docker-in-docker) shows. Renovate merges a minor or patch update on green, and opens a pull request for a major.

## Debian 13

base, ansible, ansible-aws, terraform, terraform-aws and latex move from Debian 12 (bookworm) to Debian 13 (trixie). ansible-podman already was on it, and golang stays on Alpine. The tools and paths a template relies on do not change.

A playbook that runs against the container itself and looks at `ansible_distribution_major_version` or `ansible_distribution_release` now gets `13` and `trixie`.

### What can break if you build on these images

- **The docker features.** `docker-in-docker` and `docker-outside-of-docker` default to Moby, which Debian 13 no longer has, and `devcontainer up` stops with `The 'moby' option is not supported on debian 'trixie'`. Set `"moby": false`, which installs Docker CE from `download.docker.com`:

  ```json
  "ghcr.io/devcontainers/features/docker-in-docker:4": { "moby": false }
  ```

  `devcontainer.dind.json` and the `devcontainer.docker-socket.json` profiles have it. `devcontainer.dind.json` also works with it on the v2.0.0 image it pins today, so you can set it before you upgrade.
- **Packages in your own Dockerfile.** Debian 13 renamed many libraries for its 64-bit `time_t` change: `libcurl4` is `libcurl4t64`, `libssl3` is `libssl3t64`. `apt-get install` still accepts those old names. Others are gone: `apt-get install libldap-2.5-0` fails (it is `libldap2`), and so does `software-properties-common`.
- **`apt-key` is gone.** A Dockerfile that runs `apt-key add` fails. Download the key to `/usr/share/keyrings/` and name it with `signed-by=` in the source line. apt 3.0 also verifies signatures with Sequoia, which refuses keys and signatures it considers weak, so a third-party repository can fail `apt-get update` where it passed on Debian 12.
- **`ssh` no longer has DSA.** OpenSSH 10.0 removed `ssh-dss`, so a DSA key or a server offering only a DSA host key stops working.
- **What you compile.** A binary built in the container now links against glibc 2.41 and may not run on Debian 12 or on an older host. Build it elsewhere if it has to.
- **Tools that came with the old base.** `e2fsprogs` is no longer in Debian's slim images, so `chattr`, `lsattr` and `mke2fs` are gone. `apt-get install e2fsprogs` from a root shell brings them back.
- **`apt-get install python3` on terraform or latex** now gives Debian's 3.13 instead of 3.11, on `PATH` as `/usr/bin/python3`. The images themselves use their own 3.14.10 in `/opt/devcontainer-tools`.

Existing pre-commit environments keep working: a Python hook environment built on the v2.1.0 terraform and ansible images ran on these without a rebuild.

### Base image pin

The `BASE_IMAGE` digest in `devcontainers/ansible/Dockerfile` moves as a digest update that merges on green, which is what moves the local-build ansible image to Debian 13 after main publishes the new base.

## Volumes from an earlier image

A root-owned volume that is still empty takes the owner of the image's directory the next time it is mounted, so the volumes that failed heal on their own when you rebuild the container. A volume that already holds files keeps its owner; remove it with `docker volume rm go-mod-cache go-build-cache pre-commit-cache` after removing the container, or change the owner from the host with `docker exec -u 0 <container> chown -R vscode:vscode <path>`.

## Docs

- `devcontainers/ansible/README.md` told you to select a profile by writing `"extends": "../devcontainers/ansible/devcontainer.dind.json"`. The dev container specification has no such property, and `devcontainer up` on such a file fails with `missing one of "image", "dockerFile" or "dockerComposeFile"`. The README now shows how to copy a profile instead.
- `docs/CONTRIBUTING.md`, `docs/DESIGN_DECISIONS.md` and `docs/IMAGE_OPTIMIZATION.md` no longer rely on `sudo` inside the container. To get a root shell, use `docker exec -u 0` from the host.
