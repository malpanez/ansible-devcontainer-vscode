# v2.1.0

The dev container templates and examples now open the v2.0.0 images instead of v1.4.0, and two new `devcontainer.aws.json` templates, one for terraform and one for ansible, open the `-aws` images.

- Opening a template now gives you the v2.0.0 images: `ansible-core` with `ansible.posix`, `community.general` and `community.docker` instead of the 92-collection `ansible` bundle (install any other collection from a `requirements.yml`), and no `aws` command in the plain terraform image.
- Security: the images' own Python is 3.14.10, which is what fixes CVE-2026-115557 in them. The AWS CLI in the two `-aws` images still carries its own bundled Python 3.14.8 until AWS rebundles it.
- `devcontainers/terraform/devcontainer.aws.json` and `devcontainers/ansible/devcontainer.aws.json` open `devcontainer-terraform-aws` and `devcontainer-ansible-aws`. They mount no host credentials; log in inside the container.

## AWS templates

- The templates do not bind-mount the host's `~/.aws`, so they start on a machine that has none and the container cannot read or change the host's credentials.
- `AWS_PROFILE`, `AWS_REGION` and `AWS_DEFAULT_REGION` are forwarded through `runArgs` (`--env NAME`) only when they are set on the host. An unset variable stays unset in the container; an empty one would make the AWS CLI fail with `The config profile () could not be found`.
- Log in inside the container with `aws configure` or `aws sso login --no-browser`. The login is lost when the container is rebuilt.
- To use the host's `~/.aws` anyway, add one `mounts` entry to your copy of the template; `devcontainers/ansible/README.md` and `README.md` give the line and its trade-offs.

## Examples and docs

- `examples/terraform-project` and Example 2 of the integration guide use `devcontainer-terraform-aws` and keep their explicit `~/.aws` mount; the directory must exist on the host.
- The repository's own `.devcontainer` is regenerated from the terraform template and now includes the AWS variant.
- Docs no longer state tool versions that the v2.0.0 images changed; they point to `uv.lock`, `devcontainers/ansible/collections.txt` and the `ARG` lines in the Dockerfiles. Claims that the images ship Molecule, pytest, ruff, mypy, Checkov or Trivy, which they do not, are removed where they were found.
